# Уведомление владельца о тревоге

Пустой секрет Airlock `signal_smtp` отключает почту. Владелец приложения задаёт его в конфигурации целевого PM. Нужны подтверждённый внутренний TLS relay, выделенный адрес отправителя и внутренний тестовый ящик или почтовый sandbox с ограничением получателей. Учётные записи сотрудников для отправки не используются.

Поля JSON:

- `owner_id` — UUID пользователя Airlock, которому принадлежит карточка и который запускает расследование.
- `address` — адрес внутреннего relay в формате `host:port`. Сертификат проверяется системным хранилищем доверия.
- `from`, `to` — по одному почтовому адресу без отображаемого имени. `to` задаёт оператор приложения. Инструменты и чат его не принимают.
- `tls_mode` — `starttls` по умолчанию либо `implicit` для порта с TLS с первого байта.
- `username`, `password` — оба поля можно опустить для защищённого relay без SMTP AUTH. Если relay требует авторизацию, используйте выданную для приложения учётную запись.

Письмо отправляется из `investigate_orders` после сохранения или чтения карточки по наблюдаемому `watchdog.alert=true` с подтверждённым происхождением ряда. Синтетические, неизвестные и тихие сигналы пропускаются. В письме только общая формулировка и абсолютная ссылка Airlock. Для открытия карточки действуют обычная авторизация и проверка владельца.

Ключ SMTP хранится в PostgreSQL по UUID владельца и ID сигнала. Повторный вызов возвращает карточку и пропускает отправку для принятого ключа. Ошибка до начала передачи письма освобождает ключ для следующего вызова. Если передача началась, но ответ relay потерян, повторная отправка подавляется: SMTP мог принять письмо. Bridge использует свой ключ.

Закрытый снимок доступен через авторизованные HTTP-маршруты PM. Чат может импортировать и читать его при `private_model_route=approved`. HTTP-origin вызов инструмента, MCP и фоновые HTTP-задачи не получают доступ веб-формы. Записи и снимки по-прежнему выбираются по UUID пользователя.

## Локальная проверка

```sh
GOMAXPROCS=2 GOFLAGS=-p=1 go test -count=1 -v ./internal/product ./internal/evidence -run 'Test(SignalMail|LocalEvidenceAccess|PrivateImportRequiresLocalAccess)'
```

Тестовый SMTP-приёмник слушает только loopback, требует проверяемый STARTTLS и принимает письма на адреса `.test`. Две попытки доставки проходят через общий код захвата ключа с тестовым хранилищем. Приёмник получает одно письмо и проверяет ссылку. Эта проверка не требует входа в реальный почтовый сервис.
