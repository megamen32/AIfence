Нативное приложение владельца продукта. Рабочее состояние находится в изолированном Postgres Airlock. Локальный бэклог хранит подтвержденные задачи. Порог улучшения на 10 п.п. относительно контроля и 28 дней в сценарии индекса заказов являются редактируемым предложением команды. Запуск и приемка описаны в README.md.
Отдельный research/competitive_matrix.py строит матрицу из клиентского .study JSON и сравнивает её с агентским снимком в .runtime; пропуски сохраняются явно, сторож и карточка KES не затрагиваются.

Еженедельные проверки на странице `/source-watch` используют нативную очередь Airlock. Владелец выбирает свою привязку `metrika-analyst.compare_periods` и дополнительно `metrika-analyst.compare_demand` с поисковой фразой, `market-watch.list_offers` с точным артикулом или обе. Проверка сравнивает последние две полные недели с понедельника по воскресенье по UTC. Для живой Метрики задайте счётчик и оставьте `evidence_path` пустым. Для показателей электронной торговли требуется подтверждённая инструментализация. Вордстат использует привязку владельца `wordstat` и настройку `wordstat_folder_id`. Market Watch читает уже собранные предложения.

Запуск включает еженедельную проверку по понедельникам в 06:00 UTC. Выбор прошедшего понедельника в пределах последней недели запрашивает первый разбор завершённых периодов сразу. При обычных изменениях модель не вызывается. Если Вордстат сообщает, что ещё не опубликовал обе недели, достигнутое пороговое падение Метрики запускает разбор с отметкой о недоступности спроса. При спокойной Метрике такая проверка получает статус «неполная». Опубликованный ноль учитывается как число запросов. Порог падения показателя магазина обязателен, отдельный порог падения спроса по фразе задаётся по желанию. Предложения выбранного SKU служат контекстом для оценки изменения на уровне всего магазина.

Перед включением фонового анализа привяжите разрешённую модель к слоту `source_watch_analysis`, проверьте её резервный маршрут и задайте `source_watch_analysis_route=approved`. По умолчанию анализ выключен. Смотрите результат на странице в записи проверки. Остановка прекращает будущие чтения при доставке очередного задания. Ранее начатый разбор доступен владельцу.

Приложению нужен SDK и хост Airlock с `JobContext.ReadAppTool`, `WithReadOnly` и выдачей персональных привязок к точной операции. Для проверки с неопубликованным SDK используйте отдельный Go workspace, содержащий модуль приложения и модуль SDK. Используйте отдельную рабочую область для каждого приложения, поскольку Product Manager и Market Watch имеют одинаковое имя Go-модуля.
