# AIfence repository rules

Read README.md, docs/architecture.md, contracts/README.md and your assigned docs/tracks/*.md before coding.

- Pinned private Airlock v0.8.15 and matching public agentsdk v0.11.0 ONLY; no copying closed platform source or older Product Studio implementation into the contest repository. The platform revision is pinned, not a development target.
- One application owns one independent user value. Three separate applications; no second orchestrator, no mandatory vector DB, no new data lake. Model calls via configured Airlock model; no hard-coded model keys.
- All agents work in the SAME checkout, /Users/user/AIfence, on main. Separation is by assigned directory, not branches/worktrees. Read the whole repository; edit only your assigned paths. The integration owner edits shared contracts, root instructions and deployment scripts. Never create worktrees or switch branches without the user's request.
- In the shared checkout, commit only your own explicit paths: git add -- <owned-paths>; git commit --only -m "..." -- <owned-paths>. Never use git add -A, git commit -a, git reset --hard, git clean or git stash in the shared checkout. Do not stage, revert or overwrite a sibling's changes. Coordinate any cross-directory edits with the integration owner.
- Read the official SDK instructions generated by the pinned launcher. Use SDK native auth/storage/jobs; respect caller ownership. Do not deploy generic scaffolds as real solutions. Test before deployment.
- Offline synthetic fixtures run without credentials. Distinguish live API, imported historical data, synthetic fixture, unknown/missing. Every claim has source locator; calculate numbers in code, not in LLM prose. No evidence = no asserted causality. No real profit claim without cost and volume.
- Private data and meeting recordings remain outside Git, including Git history, logs and public screenshots. Never add credentials. No external publication or actual price/priority changes without authorized confirmation.
- Record tool contracts, commands, measured tests, and honest blockers in track README or docs. Final acceptance is one user request through a real Airlock chat, not manually prebuilt artifacts.

## Product QA and demo rules (owner decision, 26.11)

Full checklist, few-shot prompts and grading: `.agents/skills/qa-testing/SKILL.md`. Load it before writing any demo, video, test or acceptance prompt.

- **No solution prompts.** A user request in a demo, video script, test or acceptance run must not contain tool names, parameters, date windows, as_of, fixture paths, file formats, metric names, target/control names, SKUs or step order, and must not pre-approve actions. Write it as a non-analyst director of digital channels would say it: vague, colloquial, sometimes wrong or with extra noise ("эээ, слушайте, по Касперскому продажи просели вроде?"). The agent chooses product, control group, windows, sources and tools itself.
- **Mechanical check before any test query.** It may contain no IDs, SKUs, file names, paths, metric names, tool or app names (Market Watch, Metrika Analyst, Product Manager), dates or windows, no named control group, no hinted conclusion ("цены относятся к разным товарам") and no restriction ("только чтение"). If even one item matches, rewrite the query. Bad examples with analysis: `.agents/skills/qa-testing/SKILL.md`, section 3.
- **Real products only, no placeholder names.** Demo, synthetic and test data shown to the user use real products from the parsed catalog (Market Watch): Kaspersky Small Office Security, Kaspersky Endpoint Security, Dr.Web, Astra Linux, MyOffice, with real SKUs (e.g. KL4141RCEFS) and plausible prices. Banned in names, labels, fixtures, generator outputs and UI strings: `demo_target`, `demo_control`, «учебный …», «тестовый продукт/пример/набор», foo/bar/baz, `product_a`, «Продукт А». Synthetic origin is marked only by a hidden flag or path (`synthetic: true`, `fixtures/`, `.runtime/blind-director/`), never by the name the user sees. Check: `python3 scripts/lint-placeholder-names.py [extra dirs]` must exit 0 before a demo, video take or acceptance run.
- **Migration note for Astra (owner of metrika-analyst / product-manager):** the lint currently fails on existing fixtures `apps/metrika-analyst/fixtures/synthetic-watch*.json`, `synthetic-after-fix.json` and strings in `apps/product-manager/handlers/monitor.go`, `main.go`, `apps/metrika-analyst/watch_schedule.go`. Rename demo_target → a real family (e.g. Kaspersky Small Office Security) and demo_control → a real control (e.g. Astra Linux), drop «учебн…» from user-visible text, update tests, then wire the lint into the test run. The blind generator outputs are already clean.
- **Ask before acting.** The agent asks for explicit confirmation before creating a backlog task or changing anything. Never put "подтверждаю" into the initial request.
- **If the agent fails on a vague request, fix the system prompt, tools and data contracts, never the request.** Do not make the question more specific to get green.
- **Answer shape:** the direct answer to the question comes first ("Цену менять не стоит: ..."). No misleading headline numbers (do not headline a spread that the answer itself later calls incomparable). Do not call a signal reliable when it is one week barely over threshold; say what would confirm it. No causality without evidence. Left chat: 3–5 short lines. Everything else (charts, prices, status) goes to the right panel as visuals.
- **One definition of signal magnitude.** The size of a drop has a single definition (window, baseline, rolling vs weekly) fixed in code and covered by tests, and every answer quotes that one number with its definition. Two runs reported −20% and −32.3% for the same 110 → 74.5; that must be impossible. Raw weekly deltas may be shown only as labelled secondary numbers.
- **UI boundary.** Do not modify the Airlock chat on the left (that is platform/driver territory). The Product Manager right panel is the wow screen: visuals, not text. Scenarios: morning map products × channels with a pulsing anomaly "найдено агентом ночью"; click → animated target vs control chart with release marker and evidence pinned to points, confidence bar "не доказано / подтверждено"; cost-of-delay counter in ₽/week; screenshot strip of the purchase-path check with the failing step highlighted; before/after that turns green; panel follows the conversation. Text on the right is captions only.
- **Astra is the orchestrator.** Delegate UI/frontend work to 1–2 subagents (frontend-design skill), lower priority than the end-to-end run; provide before/after screenshots. Do not hand-edit UI in the orchestrator loop.
- **Priority:** one end-to-end KES run through a real Airlock chat with a vague director request comes first. Then blind scenarios S7 (renamed product family), S13 (late events), S14 (masked multi-cause), S6 (bots), S12 (A/B allocation shift = honest refusal). The scorer must accept `no_alert` and `insufficient_data` as correct where the oracle says so.

## Unattended runs: no macOS Keychain prompts

The owner must be able to leave the laptop while agents work. Any keychain dialog blocks the run.

- Do not call `security find-generic-password` / Keychain APIs in loops, tests or per-case runs. Read a stand credential at most once per process, never print it, and prefer an already issued token in protected runtime.
- A keychain item created by one binary (e.g. `python3` through `SecKeychainAddGenericPassword` in `scripts/stand/save-mac-credential.py`) is trusted only for that binary; reading it later with `/usr/bin/security` (as `tests/integration/blind_director/live_adapter.py` does) triggers a password dialog every time. Read and write it with the same tool, or create it with `security add-generic-password ... -T /usr/bin/security`.
- Playwright/Chromium: keep Playwright's default `--use-mock-keychain` and `--password-store=basic`. If you pass `ignore_default_args`, a persistent context or a real Chrome channel, add both flags explicitly. Never point automation at the owner's real Chrome profile.
- Do not run `codesign`, `security unlock-keychain`, keychain imports or `git credential-osxkeychain` from agents. Git push uses SSH (`git@github.com`), no credential helper is needed.
- If a dialog still appears, stop and record which item/app it names in the track README instead of retrying.
