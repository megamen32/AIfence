# Личные релизы AIfence

Ветка `personal/integration` собирает изменения личного Product Manager и его аналитических приложений. Тег вида `personal/2026.11.27.1` отмечает проверенный срез. Общее ядро Airlock, SDK, Sol и эта ветка хранятся в отдельных приватных Git-репозиториях на 88. Точные ревизии платформы и каталог артефактов задаёт [файл релиза](../platform/personal-release.lock.json).

## Сборка приложений

Требуются Go, Python 3.12+ и штатные инструменты сборки Airlock. На Mac используется `/opt/homebrew/bin/python3`. В корне приватного checkout выбранного тега выполните:

```sh
export PATH="/opt/homebrew/bin:/usr/local/go/bin:$PATH"
python3 scripts/personal-build-apps.py --output "$PWD/.runtime/private-apps/2026.11.27.1"
```

Скрипт берёт исходники приложений из коммита Git, скачивает указанную версию SDK и Sol по SSH с 88 и формирует три архива через нативный `sourcebundle`. Каждый архив содержит проектные Go-зависимости с относительными путями. Проверка распаковывает именно передаваемый архив, запускает `go tool air build` и записывает контрольную сумму, размер и идентификатор дерева в `apps.json`. Для повторной проверки при заполненном Go-кэше можно задать `GOPROXY=off`.

Публикация исходного пакета в конкретное установленное приложение выполняется его владельцем через штатный деплой Airlock и проверку версии исходников. Выдачу привязок к Метрике и Wordstat и расписание проверки владелец задаёт отдельно в Product Manager.

## Обновление локальной платформы

Из тега Airlock возьмите `scripts/personal-release/images.py`. Подготовьте на M1 образы из `release.json`, архивов backend/frontend и квитанции образов 88. Сверьте SHA-256 с рецептом релиза. Локальный манифест для `scripts/up` содержит имена служб, исходную и локальную идентичность образа, ревизию и хеши артефактов.

`scripts/personal-mac-rollout.py` принимает `--manifest`, полный `--revision`, ожидаемую `--schema` и новый приватный `--run-dir`. Команда адресует существующий проект `aifence` в Colima и проверяет, что кандидат меняет только образы. Перед переключением она сохраняет PostgreSQL и указатели запуска, затем проверяет готовность базы, S3 и хеш главной страницы через localhost. При ошибке и прежней версии схемы она возвращает исходные образы. Для схемы с уже применённой несовместимой миграцией сохраняются резервная копия и материалы обновления.
