# Релизы AIfence из main

Исходники трёх приложений и рецепт сборки живут в `main`. [Файл профиля сборки](../platform/personal-release.lock.json) закрепляет зависимости native-сборки. Разрешённую рабочую версию определяет [общий канал релиза](#общий-замороженный-релиз). Релиз приложений всегда указывает точный проверенный коммит `main`.

## Сборка кандидата

Нужны Go 1.26.11, Python 3.12+ и штатные инструменты Airlock. На Mac используется `/opt/homebrew/bin/python3`. Поставьте Go 1.26.11 первым в `PATH`. Задайте `AIFENCE_PERSONAL_CACHE` на существующий защищённый каталог с `agentsdk-source` и `sol-source`. Если закреплённые коммиты отсутствуют, адрес разрешённого SSH-зеркала передаётся через `AIFENCE_PERSONAL_GIT`. Адрес и закрытые исходники не входят в Git приложения.

Закоммитьте кандидат вместе с рецептом сборки, затем выполните из этого checkout:

~~~sh
commit="$(git rev-parse HEAD)"
/opt/homebrew/bin/python3 scripts/personal-build-apps.py --commit "$commit" --output "$PWD/.runtime/private-apps/$commit"
~~~

`--commit` разрешает проверять интеграционный коммит до включения в `main`. Скрипт фиксирует SHA один раз и проверяет соответствие выполняемых скриптов, helper и lock выбранному коммиту. Исходники приложений берутся из Git-объектов. Helper и lock читаются из того же коммита.

Сборка использует существующий `scripts/deploy-apps --dry-run`. В staging добавляются архивы SDK и Sol из закреплённых коммитов и относительные `replace` под `.personal-modules/`. В репозитории `go.mod` сохраняет ссылки на опубликованные модули; прямые native API требуют закреплённого профиля.

Штатный `sourcebundle` формирует архив. Проверка распаковывает именно этот архив и выполняет `go tool air build`: SQLC, templ, Tailwind, `go test -p=1 -count=1 ./...` и сборку Go. `apps.json` содержит коммит приложений, версии зависимостей, хеши рецепта, идентификаторы деревьев, SHA-256 и размеры архивов. При заполненном Go-кэше можно задать `GOPROXY=off`.

## Развёртывание main

После включения проверенного кандидата в `main` интегратор развёртывает его точный SHA:

~~~sh
export AIFENCE_DEPLOY_COMMIT="$(git rev-parse main)"
./scripts/deploy-apps --dry-run
./scripts/deploy-apps
~~~

`scripts/deploy-apps` использует тот же native builder, сверяет квитанцию и распаковывает проверенный архив. Выбранный коммит должен совпадать с текущим `main` перед сборкой и перед загрузкой. Изменённые незакоммиченные скрипты или lock блокируют релиз.

Все worktree используют общий `aifence-deploy` внутри `git rev-parse --git-common-dir`. Lock и SDK binding общие для пары origin/application. Dry-run создаёт staging без lock развёртывания. Вторая live-команда для занятого приложения останавливается.

При первом переходе интегратор передаёт `AIFENCE_BINDING_FILE` для конкретного приложения: настоящий `.airlock/local/agent.toml` синхронизированного SDK checkout, исходники которого учтены в релизе. Случайный binding другой рабочей копии автоматически не импортируется. Далее используется общий state. Команды SDK явно выбирают target `production`. SDK сохраняет настоящий source ETag и проверяет CAS. Конфликт требует прочитать и объединить изменившиеся исходники; `--force` не применяется.

После релиза сопоставьте `apps.json.source_commit`, квитанции установки и live sourceRef трёх приложений. Привязки к источникам и расписание остаются в существующей установке и проверяются отдельно.

## Платформа M1

Native-профиль уже установлен на M1. Приложения используют его закреплённые SDK и Sol. `platform/airlock.lock.json` сохраняет исходный bootstrap-пин v0.8.15; native-рецепт находится в `platform/personal-release.lock.json`.

Для отдельного согласованного обновления платформы из тега Airlock используется `scripts/personal-release/images.py`. Подготовьте образы из `release.json`, архивов backend/frontend и квитанции образов, сверив SHA-256. Манифест для `scripts/up` содержит службы, идентичность образов, ревизию и хеши.

`scripts/personal-mac-rollout.py` принимает `--manifest`, полный `--revision`, ожидаемую `--schema` и новый защищённый `--run-dir`. Он адресует существующий проект `aifence` в Colima, проверяет изменение образов, сохраняет PostgreSQL и указатели запуска, затем проверяет базу, S3 и localhost. При ошибке и прежней схеме возвращает исходные образы. Для несовместимой миграции сохраняются резервная копия и материалы обновления.

## Общий замороженный релиз

Рабочий набор Airlock, AgentSDK и Sol определяется опубликованным `releases/current/channel.json` личного канала на 88. На M1 интегратор переносит его точную проверенную копию вместе с `release.json` в `~/AIfence/.runtime/personal-releases/current/`. Документация и рабочие ветки не выбирают другую версию.

`scripts/personal-mac-rollout.py` всегда проверяет целостность этой копии: `platform_manifest_sha256` должен совпадать с байтами соседнего `release.json`, а `components.airlock/agentsdk/sol` с его `core/agentsdk/sol`. Отсутствующая или повреждённая копия останавливает выкладку до обращения к Docker и создания lock. Коммит приложений `components.aifence` относится к отдельному пакету приложений.

При `frozen: true` допускается только этот платформенный манифест целиком. Рядом с переданной квитанцией образов должен находиться его `release.json`; совпадают все три коммита, SHA-256 манифеста и архивов backend/frontend. Существующая проверка происхождения Docker-образов сохраняется. Политика проверяется до изменений и повторно под `release.lock` после резервного копирования и ожидания свободных запусков, перед переключением контейнеров.

Подготовка и сборка кандидатов продолжаются независимо. Смену рабочего набора интегратор проводит через общий канал и его явную разморозку. Значение `frozen: false` и прежний канал без этого поля сохраняют согласованную явную выкладку, но требуют корректной утверждённой копии канала. Локальный файл `channel.json` рядом с кандидатом не меняет разрешённый релиз.
