# S14. Непрерывная запись на Mac M1

`./run-s14 fresh` подготавливает выделенную учётную запись на локальном конкурсном стенде, открывает видимый Chromium и вводит вопрос директора в Airlock. `./run-s14 review` открывает существующую карточку S14 и проводит зрителя от карты каталога до графика «После релиза». Каждый запуск снимает собственный немой дубль. В режиме review задача уже существует до начала записи.

## Запуск

```sh
cd /Users/user/AIfence-worktrees/s14-one-take-recorder-20261127/docs/submission/s14-take
./run-s14 doctor
./run-s14 fresh
```

Для показа сохранённого кейса выполните `./run-s14 review`. По умолчанию новая запись попадёт в каталог с уникальным именем внутри `~/AIfence/.runtime/s14-demo-takes/`. Для другого места передайте `--out /путь/к/новой-папке`. Учётные данные используются до открытия записываемой страницы. На рабочем столе остаются доступными другие окна.

Для текущего Mac подготовлены локальный Airlock на порту 42080, приложения Product Manager и Metrika Analyst, Chromium и Python 3.11 с Playwright 1.60. Запись идёт из области веб-страницы. Компоновку интерфейса, системные элементы macOS и разрешение на запись всего экрана настраивать не требуется.

## Входные данные и вопрос

Сценарий описан в `.agents/skills/qa-testing/SKILL.md` репозитория AIfence. Вопрос директора фиксирован.

> слушайте, может нам цену на Касперского снизить? продажи вроде упали, конкуренты наверное дешевле

Для свежего запуска скрипт читает пять файлов канонического синтетического набора. Это `manifest.json`, `metrika.json`, `Продажи.xlsx`, `releases.json` и `backlog.json`. Штатный преобразователь в установленном репозитории AIfence подготавливает наблюдения для источников. Подготовка проверяет владельца, пустую историю, выбранный набор данных, число снимков и чтение конкретного числового наблюдения. Приватные учётные данные нового владельца остаются в `owners/` на Mac. Для другого рабочего дерева пути к замороженным входам и к адаптеру можно задать через `AIFENCE_S14_INPUTS` и `AIFENCE_QA_ROOT`.

```sh
./run-s14 prepare --check-only --inputs "$AIFENCE_S14_INPUTS"
./run-s14 fresh --profile /путь/выделенного-владельца/access.json --out /путь/к/новому-дублю
```

Собственный профиль должен содержать отдельную учётную запись стенда и подходящие источники. Оператор запускает следующий независимый эксперимент на новом владельце. Нативный POST проходит только с выбранным Product Manager и путём `/`. Скрипт сверяет его с первым вопросом и сверяет ответ в браузере с сохранённым сообщением этого же разговора. Отдельная проверка первоисточников читает две строки оформлений именно из снимка данного владельца. Действия оператора после ответа помечаются в журнале отдельно от действий модели. Учётную запись демонстратора со старой гипотезой использует режим review. На локальном стенде раздельная панель в iframe отвечает ошибкой SSO. Рекордер использует штатное представление «Развернуть чат» с выбранным Product Manager. После ответа он открывает подтверждённые первоисточники верхней страницей в той же вкладке.

При осознанном разрешении создать демонстрационную задачу передайте `./run-s14 fresh --confirm-demo-task`. Разрешение касается только кнопки подтверждения конкретной новой карточки в локальном демобэклоге. Вопрос директора остаётся прежним.

## Проверка

```sh
./run-s14 verify /путь/дубля/take.webm /путь/дубля/take.mp4 --receipt /путь/дубля/receipt.json
```

`take.webm` сохраняет исходную запись Playwright. `take.mp4` содержит её полный транскод. `receipt.json` связывает запись с режимом, монотонной шкалой событий и контрольными суммами. Для нового разговора записываются его идентификатор и фактически прочитанный ответ. Проверяющий скрипт декодирует оба видео, сверяет время и уменьшенный яркостный отпечаток каждого кадра и проверяет верхнюю границу в 180 секунд. Смысл ответа оценивается отдельно от технической целостности файла.

## Озвучка после записи

Отметки из журнала дают опорные времена для реплик. Подготовьте отдельный WAV по фактическому дублю. Команда ниже добавляет WAV, в котором паузы уже расставлены от начала дубля, и копирует видеопоток без перекодирования.

```sh
ffmpeg -i take.mp4 -i voice.wav -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -af apad -shortest -movflags +faststart take-voiced.mp4
```

Немой оригинал остаётся отдельным файлом. Для конкурсной версии происхождение голоса согласуется отдельно. В монтажном фильме «Не снижайте цену» диктор был синтезирован, а музыка и фоли создавались специально для него.

## Установка на другом рабочем месте

Для скриптов записи нужны зависимости из `requirements.txt`, Chromium и рабочий FFmpeg с H.264. Для независимого свежего запуска также нужны доступ к локальному конкурсному стенду, его операторская сессия, проверенная рабочая копия AIfence и перечисленные синтетические файлы. Сами ключи, cookies и пароли в комплект не входят.

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
export AIFENCE_TAKE_PYTHON="$PWD/.venv/bin/python"
./run-s14 doctor
```

В ZIP папка `runs/` содержит исходные WebM, удобные для просмотра MP4 и квитанции двух снятых дублей. В репозитории хранятся скрипты.

На существующем Mac `doctor` проверяет установленный Chromium реальным запуском. При необходимости конкретный рабочий бинарник FFmpeg указывается через `AIFENCE_FFMPEG`.
