# Gemma 4 64K: verified native and stand-LAN acceptance, 2026-11-26

## Real long-context requests

Synthetic archive with independently generated marker values at approximately
5%, 50%, and 95% of the prompt. Both requests recovered all 3 markers.

| Path | Model | Actual prompt tokens | Output tokens | Wall time | Result |
|---|---|---:|---:|---:|---|
| server-44 native Ollama /api/chat, explicit num_ctx=65536 | gemma4:latest | 61607 | 47 | 25.640 s | pass |
| server-100 LAN to native OpenAI-compatible /v1/chat/completions, no num_ctx override | gemma4:aifence-64k | 60614 | 133 | 26.328 s | pass |

First request: 13.931083 s prefill; 4422.27 input tokens/s; 9.325376312 s
model load; peak GPU used 9105 MiB; minimum free 2806 MiB. Other shared GPU
processes remained active. These are single-request observations, not a
concurrent load guarantee.

## Dedicated profile

Created the native Ollama alias gemma4:aifence-64k with:

    FROM gemma4:latest
    PARAMETER num_ctx 65536

The manifest reuses the exact existing model weight blob. Verified the alias
parameter, model capabilities, and discovery via the OpenAI endpoint from
server-100. The second full-window request established that the profile's
default context works through the OpenAI adapter, not merely the native API.

This test left Ollama, LiteLLM, the shared queue and model defaults as they
were. The shared queue and the existing aliases had an 8192-token limit.
Registration of the 64K profile in Airlock had yet to be verified at the time
of this test. See the [stand runbook](../../qa/stand.md) for the later
configuration. Confirm full product behavior, usage, vision and tool
capabilities in a synthetic app/chat request on the server stand.

## Stand verification

The server-100 isolated Airlock is reachable on the Mac via its SSH tunnel:
http://localhost:42081/. Product Manager and Metrika Analyst deployments were
active and running. On the deployed Metrika Analyst, the authorized native
SDK replay on the embedded synthetic fixture completed and returned false,
true, null for 2023-02-13, 2023-02-20, and 2023-02-27 respectively. No customer
data, real backlog changes or email were involved.

During this test the candidate public hostname failed TLS validation.
The Mac later failed to resolve the name. See the [HTTPS cutover
report](../stand-public-handoff.md) for the subsequent ingress check.
These results cover model-route and SDK probes. Full KES acceptance on the
64K profile is tracked separately.
