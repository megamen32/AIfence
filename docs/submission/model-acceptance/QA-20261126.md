# Gemma 4 model acceptance handoff

Date: 2026-11-26. All requests described here used synthetic inputs only.
This is not acceptance of the end-to-end customer KES scenario.

## Verified

- Existing Airlock OpenAI-compatible provider OmniRoute discovered the explicit
  local Gemma alias. The new catalog entry was saved with 8192 context and
  2048 output tokens. All 19 previous model configurations had the same
  metadata checksum before and after. Workspace defaults were not changed.
- The upstream Ollama model is Gemma 4, 8B Q4_K_M, with a nominal context of
  131072; the actual queue/runtime route is capped at 8192.
- Before the network correction, the model route returned proxy connection
  timeout (502, UND_ERR_CONNECT_TIMEOUT); the nonstream browser probe timed
  out at 90 seconds. HTTP 200 response headers without delivered text did
  not count as streaming success.
- A connection-scoped proxy flag was switched from enabled to disabled on
  the selected local provider connection, after the host and native Node
  client had demonstrated direct reachability. Other connection proxy
  settings were verified unchanged. No service restart or new credentials.
- After the change, a nonstream response arrived in 2.084 seconds (41
  reported tokens). This was transport success; the model echoed extra text.
- A separate exact-answer nonstream test passed in 13.270 seconds, and a
  streaming test passed in 0.127 seconds. Each reported 21 input and 2
  output tokens. Cache effects and other workload delays are not isolated,
  so these are observations, not throughput or production cost guarantees.

The initial vision probe exhausted its 96-token output allocation; a final
image answer was not verified. The expanded acceptance suite gives tools 256
tokens and vision/evidence 512 tokens. Do not reclassify the original failure
as a pass. The remaining router tool, vision and evidence results were not
independently verified in this session.

## Acceptance rule

Run the checked-in model_acceptance.py against the exact deployed model route.
The offline tests pass 7/7. Require useful text, a completed stream, a valid
tool call, correct synthetic image recognition and preservation of missingness,
causal uncertainty and human approval in the evidence case.

Then run the actual Airlock AIfence scenario on the final open-model stand.
Keep inputs small enough for the effective context cap; provide computed
evidence rather than dumping the entire workbook. Capture actual usage and
latency through scripts/measure-chat. Do not assert model/vision readiness
from catalog capability flags alone. Do not use private customer data in
unverified routes. The open model's real cost and full product acceptance
remain open.

If the scoped proxy change must be undone, restore its prior setting on
that same local provider connection only; do not alter other providers,
global proxies, or workspace model defaults.
