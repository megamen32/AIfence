# Экономика: шаблон для сдачи

Числа и их источники хранятся вне Git. Расчёт работает без зависимостей. Заполните JSON в игнорируемом `data/` и сохраните там же закрытую таблицу источников: для каждого поля значение, единица, период, источник/локатор, дата, автор и статус «из данных», «измерено» или «допущение заказчика». Публикация возможна только после разрешения на конкретные значения.

```json
{
  "input_tokens": null, "output_tokens": null,
  "input_rub_per_million": null, "output_rub_per_million": null,
  "compute_rub_per_hour": null, "run_seconds": null,
  "other_rub_per_run": null, "runs_per_week": null,
  "baseline_orders_per_week": null, "observed_orders_per_week": null,
  "contribution_rub_per_order": null, "weeks_earlier": null,
  "recoverable_fraction": null
}
```

```sh
python3 docs/submission/economics.py data/economics-input.json
```

Пустое значение даёт `null`, а не ноль. Для нулевой ставки или отсутствующих дополнительных расходов вводите 0 только после проверки. Все суммы в рублях, на единой налоговой базе; не учитывайте одну и ту же стоимость в тарифе токенов и аренде вычислений. Отдельно фиксируйте курс, если исходный тариф в другой валюте. При локальном развёртывании токены и нулевой тариф модели нужно измерить/обосновать, а стоимость вычислений считать отдельно. Результат не округляется; для формы округляйте только отображение.

| Поле | Что измерить или согласовать |
|---|---|
| input_tokens, output_tokens | Суммарные токены всех вызовов одного полного прогона, включая повторы; метаданные провайдера/сервера модели. Если недоступны, оставить пустыми. |
| input_rub_per_million, output_rub_per_million | Фактический тариф входа и выхода на миллион токенов на дату расчёта; для локальной модели обосновать ноль. |
| compute_rub_per_hour | Стоимость выделенной мощности в час за тот же период; указать метод распределения общих ресурсов. |
| run_seconds | Измеренное время полного прогона, включая ожидание; при почасовой тарификации мощность должна быть выделена на весь период. |
| other_rub_per_run | Прочие подтверждённые затраты на прогон, не включённые выше. |
| runs_per_week | Плановая частота всех сопоставимых прогонов в неделю. Для разных типов прогонов считать отдельно и сложить недельные итоги. |
| baseline_orders_per_week, observed_orders_per_week | Средние фактические количества заказов за сопоставимые полные недели, с фильтрами и источником; индекс продаж не является количеством заказов. |
| contribution_rub_per_order | Маржинальный вклад одного заказа: цена без налога минус переменные затраты на той же базе, с учётом структуры заказов. Согласовать с заказчиком. |
| weeks_earlier | Обоснованная разница во времени обнаружения в неделях, а не длительность самого падения. |
| recoverable_fraction | Сценарная доля предотвращаемого разрыва от 0 до 1; согласовать, не выдавать за измеренный эффект. |

Формулы: модель = (входные токены × тариф входа + выходные × тариф выхода) / 1 000 000; вычисления = ставка × секунды / 3600; прогон = модель + вычисления + прочее; неделя эксплуатации = прогон × число прогонов. Разрыв заказов = max(0, базовые − наблюдаемые). Сценарный потенциал раннего обнаружения = разрыв × вклад на заказ × недель раньше × предотвращаемая доля. Это сценарий при неизменном недельном разрыве и возможности восстановления, не доказанная прибыль, не причинный эффект и не оценка ROI. При отрицательном вкладе эта модель неприменима. Затраты на внедрение и исправление, сезонность и динамика восстановления сюда не входят.

Для подачи зафиксировать отдельно: полный замер времени, токены и стоимость, источники тарифов, рабочую модель и её конфигурацию; число запусков, фактические объёмы и вклад, срок и долю предотвращения. Пока входы или разрешение не получены, показывать «не измерено» и формулу без результата.
