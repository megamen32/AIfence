На 26 ноября 2026 г. измерено потребление двух синтетических QA-запросов Product Manager. Стоимость финального запуска и финансовый эффект пока неизвестны.

| Повторная проверка статуса измерения | 2 | 47 236 | 314 | 39,13 |

Источник — агрегаты Airlock `runs`, штатный `scripts/measure-chat`, локальный пакет измерений от 26.11. [История сценариев](../../apps/product-manager/qa/README.md) и [инструкция для повторного замера](economics-handoff.md). Точный модельный маршрут и тариф этих запросов не зафиксированы. Токены суммируются по вызовам, поэтому превышение контекстного окна в сумме допустимо. Эти цифры нельзя переносить на финальный KES-прогон с Gemma.

Отдельный синтетический Go-микробенчмарк `TestWatchdogScheduledCanary` дал медиану **0,652 мс на итерацию** в пяти сериях по 1 000 итераций, без вызовов модели. Это локальный замер теста. Сеть, уведомления и эксплуатационная стоимость расписания в нём отсутствуют. Источник — `watchdog-benchmark.json` из [локального пакета](economics-handoff.md).

## Стоимость эксплуатации

В рублях на одной налоговой базе. Если вычисления включены в тариф API, не учитывать их второй раз. Для тарифа в другой валюте записать курс и дату. Рублёвый итог остаётся пустым, пока неизвестна хотя бы одна применимая ставка.

- Модель за прогон = (токены входа × тариф входа + токены выхода × тариф выхода) / 1 000 000.
- Вычисления за прогон = ставка в руб/час × секунды выделения ресурса / 3600. Скрипт использует продолжительность прогона, если ресурс тарифицируется на всём этом интервале.
- Неделя эксплуатации = сумма по типам запусков: (модель + вычисления + прочие расходы) × число запусков данного типа. Нативное расписание и модельные расследования замеряются раздельно.

## Цена задержки

Потенциал раннего обнаружения = max(0, базовые заказы за неделю − наблюдаемые заказы за неделю) × маржинальный вклад на заказ × недель раньше × предотвращаемая доля. Вклад — цена без налога за вычетом переменных затрат на той же базе. Заказы нужны в штуках за сопоставимые полные недели. Индекс заказов не переводится в штуки без исходного объёма.

Пример арифметики, все входы условные: 1 000 базовых и 900 наблюдаемых заказов в неделю, 1 000 ₽ вклада на заказ, на одну неделю раньше, доля 25%. Потенциал по калькулятору — **25 000 ₽** за эту неделю. Условие — разрыв сохранялся бы всю неделю и четверть можно предотвратить. Потенциал не учитывает стоимость исправления, сезонность и динамику восстановления. Фактический эффект и ROI требуют замера после вмешательства.

## Входы для калькулятора

Заполнить JSON в игнорируемом `data/` и указать источник, дату, единицу и статус каждого значения. Пустое значение даёт `null`. Ставку или расход 0 вводить при подтверждённом отсутствии платы.

```json
{
  "input_tokens": null, "output_tokens": null,
  "input_rub_per_million": null, "output_rub_per_million": null,
  "compute_rub_per_hour": null, "run_seconds": null,
  "other_rub_per_run": null, "runs_per_week": null,
  "baseline_orders_per_week": null, "observed_orders_per_week": null,
  "contribution_rub_per_order": null, "weeks_earlier": null,
  "recoverable_fraction": null
}
```

```sh
python3 docs/submission/economics.py data/economics-input.json
```

| Входы | Основание |
| --- | --- |
| `input_tokens`, `output_tokens`, `run_seconds` | Полный замер на выбранном маршруте модели, включая повторные вызовы. `scripts/measure-chat` даёт длительность и токены. При `usage_reported=false` токены остаются пустыми. |
| `input_rub_per_million`, `output_rub_per_million`, `compute_rub_per_hour`, `other_rub_per_run` | Подтверждённый тариф либо оценка выделенной мощности с методом распределения общих расходов. Указать, что входит в прочие затраты. |
| `runs_per_week` | Измеренная или явно плановая частота данного типа запуска. |
| `baseline_orders_per_week`, `observed_orders_per_week`, `contribution_rub_per_order` | Фактические сопоставимые объёмы и маржинальный вклад. |
| `weeks_earlier`, `recoverable_fraction` | Сравнение сроков обнаружения и сценарная доля от 0 до 1 с явным основанием. |
