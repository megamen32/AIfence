В этом пространстве используются синтетические показатели, публичные SKU и цены, демонстрационный бэклог. Маршрут для жюри после входа: открыть Product Manager из списка приложений и задать вопрос из [сценария](demo.md). Этот маршрут проверяется из чистого браузера 28.11 в 09:00 (UTC+5).

На закреплённой версии стенда запуск сохранённого JS-файла с параметрами возвращает `executor does not support structured script args`. Сбор через обычный `run_js` проверяется по квитанции общего файла. Для заранее импортированного снимка укажите источник и дату. [Инструкция по обмену](../../workflows/README.md).

## Обновление серверного стенда

Итерации и прямые проверки выполняются на локальном Mac. КТ5 проводит серию из 3–5 кейсов на фиксированной ревизии 27.11 с 18:00 до 21:30 (UTC+5). Запись начинается после 22:00 по итоговой таблице. Интегратор поочерёдно вносит проверенные коммиты из рабочих деревьев в чистый синхронизированный `main` и публикует результат в приватный origin.

Версионируемые настройки и скрипты первоначального развёртывания находятся в [`scripts/stand/`](../../scripts/stand/). Параметры доступа и секреты хранятся в защищённом runtime. Для существующего стенда используйте действующие привязки SDK на его HTTPS origin. Скрипты первоначальной установки предназначены для нового экземпляра. Бюджет ресурсов и ограничения обновления описаны в [операторском руководстве](../qa/stand.md).

Из чистого интеграционного checkout после `git fetch origin main` укажите полный SHA проверенного коммита. После штатного входа SDK выполните dry run и обновите приложения с тем же SHA.

```sh
export AIRLOCK_URL=https://aifence.bezrabotnyi.com
export AIFENCE_DEPLOY_COMMIT='VERIFIED_COMMIT_SHA'
(cd apps/market-watch && go tool air login "$AIRLOCK_URL")
git merge-base --is-ancestor "$AIFENCE_DEPLOY_COMMIT" origin/main &&
  ./scripts/deploy-apps --dry-run
```

После успешной подготовки запустите `./scripts/deploy-apps` с теми же переменными и дождитесь статуса каждого приложения. В демонстрационном пространстве используйте синтетические входы из [инструкции Product Manager](../../apps/product-manager/qa/README.md) или [слепого сценария](../../tests/integration/blind_director/README.md). Для проверки свежего сбора установите [сохранённый workflow](../../workflows/README.md) в файловый каталог демонстрационного пользователя. Из обычного чата проверьте, что workflow создал доступный этой роли снимок и чат передал его JSON в `Product Manager.import_evidence`. Если показ использует ранее подготовленный снимок, зафиксируйте его происхождение. Запишите SHA, результат запроса и наблюдаемые ограничения.

26 ноября dry run из `d23f1fd` подготовил три пакета без сборки или выкладки. Серверная приёмка фиксируется отдельно.

Локальный Airlock v0.8.15 для QA доступен через `http://localhost:42082` в изолированном проекте Colima. Ответ `/health` вернул HTTP 200 с `db=true` и `s3=true`. Это проверка инфраструктуры. ## Локальная разработка на Mac

Для разработки можно запустить отдельный Airlock через `./scripts/up`. Нужны Docker с Compose, Python 3.11+ для скрипта развёртывания, Go из [пина платформы](../../platform/airlock.lock.json), доступ к Airlock Enterprise v0.8.15 и разрешённый провайдер модели. На Mac скрипт использует изолированный профиль Colima `aifence`. Образ доступен из разрешённого кеша или через авторизованный upstream.

Локальный Airlock доступен на `http://localhost:42080`. Активируйте его по подсказкам скрипта. Для локальной проверки приложений войдите через CLI на этот origin и укажите его в `AIRLOCK_URL`. Результаты локальной проверки относятся к разработке.
