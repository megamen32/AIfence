# Стенд для жюри и развёртывание

**Стенд** — [aifence.bezrabotnyi.com](https://aifence.bezrabotnyi.com/). **Вход в чат** — [открыть Airlock](https://aifence.bezrabotnyi.com/chat).

26 ноября 2026 г. обычный HTTPS GET без авторизации и с проверкой TLS вернул HTTP 200 для `/`, `/chat` и `/health`. Первые два маршрута вернули HTML Airlock. Проверка здоровья вернула `status=ok`, `db=true`, `s3=true`. Это проверка доступности сервиса. Историческая проверка после переключения HTTPS зафиксировала анонимный 401 на поддомене Product Manager. [Операторская запись](stand-public-handoff.md).

Для интерактивной проверки нужен отдельный участник демонстрационного пространства с доступом к Product Manager, Market Watch и Metrika Analyst. Оператору предстоит проверить приглашение в чистом профиле от имени жюри и передать его отдельно. В этом пространстве используются синтетические показатели, публичные SKU и цены, демонстрационный бэклог. Маршрут для жюри после входа: открыть Product Manager из списка приложений и задать вопрос из [сценария](demo.md). Приёмку этой цепочки фиксируют чаты A и B.

## Локальный экземпляр для оператора

Требуются Docker с Compose, Python 3.11+ для развёртывания приложений, Go из `platform/airlock.lock.json`, доступ к закреплённому Airlock Enterprise v0.8.15 и разрешённый провайдер модели. На Mac скрипт использует изолированный профиль Colima `aifence`. Образ платформы можно взять из разрешённого кеша или собрать из авторизованного upstream. Исходник платформы не входит в комплект.

```sh
./scripts/up
```

Открыть локальный Airlock на `http://localhost:42080`, активировать его по подсказкам скрипта, настроить модель и войти штатным CLI. Указать точный проверенный коммит в `AIFENCE_DEPLOY_COMMIT`. Пример ниже использует HEAD чистого синхронизированного checkout. Предварительная проверка читает только отслеживаемые файлы из выбранного коммита и подготавливает три пакета без сборки и загрузки.

```sh
(cd apps/market-watch && go tool air login http://localhost:42080)
export AIFENCE_DEPLOY_COMMIT="$(git rev-parse HEAD)"
AIRLOCK_URL=http://localhost:42080 ./scripts/deploy-apps --dry-run
AIRLOCK_URL=http://localhost:42080 ./scripts/deploy-apps
```

26 ноября dry run из `d23f1fd` подготовил все три пакета. При реальном запуске дождаться штатного статуса каждого приложения. В чистом пространстве добавить синтетические входные данные из [инструкции Product Manager](../../apps/product-manager/qa/README.md) или [слепого сценария](../../tests/integration/blind_director/README.md). Проверить, что источники и действия видны только разрешённому пользователю. Затем проверить ответ через обычный чат.

Для уже работающего публичного стенда оператор использует отдельную авторизацию SDK на его HTTPS origin и существующие привязки приложений. Порядок работы с ресурсами, обновления и проверки описан в [операторском руководстве](../qa/stand.md). Скрипты bootstrap предназначены для нового экземпляра. Этот документ описывает развёртывание и доступ к действующему стенду, операторские команды на нём в рамках трека C не запускались.
