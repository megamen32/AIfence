## 1. Подход и архитектура

AIfence — автономный контур развития продукта для продакт-менеджера интернет-магазина. Агент сам следит за сигналами, ищет причину отклонения, сверяется с бэклогом и доводит результат до PM, не дожидаясь вопроса.

Работает это так. Источники данных — отдельные приложения на платформе Airlock: Market Watch (цены конкурентов), Metrika Analyst (Яндекс.Метрика), Wordstat, Google Trends, Web Scraper. Приложение Product Manager (PM) собирает их наблюдения, считает отклонения кодом и только потом отдаёт модели короткий разбор. Детектор — обычный код без модели: сравнивает затронутую группу с контролем и пишет порог и окно. Модель объясняет причину и предлагает один дешёвый тест, ссылаясь только на ID наблюдений.

Фоновый контур: раз в час `sync_backlog` сверяет подтверждённые сигналы с Redmine через MCP, при совпадении добавляет комментарий в существующую задачу, иначе создаёт новую с пометкой «Сгенерирована ИИ-помощником». Каждый день в 09:00 (UTC+5) `morning_dion` отправляет сводку в Dion. Эти задачи модель не вызывают. Baserow хранит таблицы наблюдений. Чат нужен для вопросов человека, а не для запуска контура.

Принципы: числа считает код, а не модель; нет источника — нет утверждения о причине; недостающие данные называются «неизвестно», а не нулём.

## 2. Стек и модели

Платформа: Airlock v0.8.15 (закрытая, версия закреплена в `platform/airlock.lock.json`), SDK `airlockrun/agentsdk` v0.11.0. Приложения на Go: templ, htmx, Tailwind + daisyUI, PostgreSQL. Интеграции: Redmine и Dion (через UserIO) по MCP, Baserow, Яндекс.Метрика через `yandex-metrica-mcp`. Список библиотек и лицензий: [models-and-prior-work.md](models-and-prior-work.md).

Модели в продукте: только открытые веса, до 128 ГБ VRAM в Q4 (класс Qwen), на GPU заказчика. Проверенный маршрут — Gemma 4 8B (Q4_K_M, Apache-2.0) через Ollama, окно 64K: prefill 4 422 токена/с. **[проверить]** Целевая модель класса Qwen на стенде ещё не прогонялась. При разработке и демо-прогонах использовались закрытые модели (Terra, Sol); в продукт они не входят.

## 3. Что сделано за 48 часов, что нет

Сделано и проверено: пять источников данных и PM; детектор отклонений с контролем; цикл «сигнал → задача в Redmine → сводка в Dion» на ДЕМО-реплее на стенде Mac (порт 42080): сигнал дал задачу Redmine #8, повторный запуск не создал дубль, отправка в Dion сработала; промпт PM переписан так, чтобы причина шла первой (на 30 dev-кейсах 19/20, ложных тревог 0).

Не сделано или ограничено, честно:
- На закрытом (sealed) наборе детектор нашёл 11 из 22 отклонений, ложных тревог 0; сценарий S14 (оформление заказа при росте трафика) 0 из 6. Dev-кейсы 20/20 взяты из того же генератора, на котором настраивали детектор, так что это не оценка на новых данных.
- Финальный прогон на целевой открытой модели (Qwen-класс) и полный замер токенов на ней не сделаны; цифры стоимости опираются на замеры на закрытом маршруте.
- Недельный `check_source_watch` на стенде расписанием не подтверждён. **[проверить]**
- Данные ДЕМО синтетические; реальных данных заказчика в контуре нет. Эффект на продажи не измерялся.
- Публичного стенда нет. Стенд работает на Mac.
- Файла LICENSE на исходный код пока нет.

## 4. Запуск и поставка

Стенд: Airlock на Mac, `http://localhost:42080`, развёрнуто `scripts/up`; приложения выкладываются `scripts/deploy-apps` с `AIFENCE_DEPLOY_COMMIT` = проверенный SHA из `main`. Redmine, Baserow и MCP-шлюз Redmine поднимаются Docker Compose (`scripts/stand/`). После развёртывания в Airlock задаются: MCP-ключ `redmine`, MCP-токен `userio`, переменные `redmine_project`, `dion_test_chat`. Секреты хранятся вне Git.

Для заказчика: Docker Compose на их сервере плюс GPU-сервер с открытой моделью (подключается как модельный слот Airlock). Перенос стенда на сервер одной командой: `scripts/stand/move-to-server100.sh`. Пилот — одна продуктовая линия и один PM; ориентир затрат в [расчёте](economics-cost.xlsx).
