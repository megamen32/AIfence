# Правило слепого replay для sourcewatch

Зафиксировано до следующей сверки результатов с эталонами. На уже исследованных кейсах 01/06 новая попытка не считается независимым слепым подтверждением: их прошлые результаты и часть причин известны.

1. Для каждого нового набора до обращения к его эталону вывести все пары соседних полных недель понедельник–воскресенье из фактически доступных рядов. Исключить недели после `as_of`, неполные недели и строки без проверенного значения, единицы, области и локатора. Не выбирать одну дату по результату и не подменять семейный ряд рядом `store`.
2. Запустить неизменённый `sourcewatch.Check` на каждой допустимой паре с одинаковыми заранее объявленными настройками. Результат каждого окна, его входные хеши и ошибку записать в отдельный неизменяемый закрытый файл; не передавать эталон в `Read` или параметры вызова.
3. Заморозить результаты **всех** окон всех проверяемых кейсов и только потом открыть соответствующие эталоны. Отдельно учитывать сигнал в эталонном окне, сигнал вне окна, отсутствие сигнала, ложную тревогу на отрицательном кейсе, неподдерживаемый контракт и неполные данные.
4. `submitted` означает только срабатывание порога и запуск заглушки/анализа. Это не доказательство скрытой причины. Совпадение семантической причины и действия оценивается отдельно по фактическому ответу модели и источникам, а не по статусу сторожа.
5. Долю обнаружений показывать как число положительных кейсов с допустимым сигналом в эталонном окне / число положительных кейсов, пригодных для оценки. Долю ложных тревог — число пригодных отрицательных кейсов хотя бы с одной тревогой / число пригодных отрицательных кейсов. Неполные и несовместимые случаи показывать отдельными количествами; знаменатель 0 означает «не определено», а не 0%. Для КТ3 нужны не менее 30 самостоятельных сценариев; повторные окна одного кейса не увеличивают число сценариев.

Минимальная исходная синтетическая строка для поддерживаемого семейного контракта: семейство `kaspersky_small_office_security`, метрика `visits`, значение `614 count`, период 05–11.01.2026, сегмент `desktop`, `source_id=blind-metrika`, локатор `week=0;family=kaspersky_small_office_security;device=desktop;metric=visits`, ревизия `synthetic-v2`, `synthetic=true`, `origin=synthetic_fixture`. Это исходное наблюдение, не сравнение окон и не утверждение о живом счётчике. Публичный контракт должен явно передавать scope семейства, сегмент, две полные недели, исходные единицы и честные локаторы; выход сравнения фиксируется отдельно. SKU в данных — `KL4141RCEFR`. Для кейсов 07–11 исходной Метрики нет; отдельный синтетический контрпример не следует выдавать за исходное или реальное наблюдение.
