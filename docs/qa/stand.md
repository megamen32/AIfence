The public origin is <https://aifence.bezrabotnyi.com/>. The current HTTPS vhost forwards the apex, app subdomains and S3 subdomain to the stand's loopback Caddy proxy; it preserves Airlock login and does not use the personal Airlock.

The active default execution model is `gemma4:aifence-64k`; the separate build default is `gemma4:latest`. The model runtime reports a 65536-token context for the execution profile. A previous synthetic canary passed on the earlier model; this document does not assert a fresh execution canary for the 64K profile. Use authorized data and configured provider policies; do not copy personal settings or credentials.

The live Airlock container has no `AIRLOCK_BACKGROUND_ACTIONS_PAUSED` setting, so the pinned platform's default is active. There is no live `compose.stand.yml` override. A paused override generated by an older local setup script was never applied; do not introduce one implicitly. The pinned platform can start two background cache warmups on restart: avoid restarting during another heavy workload. The standalone bootstrap script requires an explicit background-action choice and refuses any existing `.env`.

## Resource and deployment controls

The isolated daemon's shared cgroup has memory high 4 GiB, max 6 GiB, swap 0, CPU quota 200%, tasks max 1024 and NVMe reads/writes each 50 MB/s. Rootless Docker reports cgroup driver `none`: the shared outer cgroup, not individual Docker limits, is the effective bound. Its 40 GiB ext4 loop image bounds this daemon's images, Docker state and volumes. One heavy workload at a time. No project Git checkout is needed on the server; normal SDK app admission and owner bindings remain required.

The SDK CLI must target the public Airlock origin for public deployments. Existing local bindings and active chat scopes belong to their original origin; do not silently rewrite them or restart Airlock while sessions are in progress. Operator-specific addresses, paths and stand-only credentials remain in protected runtime or the operator's keychain, never Git.

The enabled certbot renewal timer uses DNS-01 hooks with the stand's private `acme-dig.sh` wrapper; the wrapper corrects the existing shared hook's zone-relative authoritative lookup without changing that shared hook. ## Stand scripts

`setup-host.sh` provisions a new dedicated user, bounded disk and rootless daemon and refuses existing names. `start-runtime.sh` is **new-stand bootstrap only**: it refuses an existing `.env`, requires a public hostname, trusted gateway and explicit background-action decision, and does not change the live stand. `configure.py` likewise refuses an activated stand and defaults to the observed execution and build model IDs for a new stand. `import-from-cache.py` and `import-image.py` import pinned release images one at a time; `model-canary.py` sends a synthetic prompt to an explicitly supplied origin; `save-mac-credential.py` stores the isolated operator login in the Mac keychain. `acme-dig.sh` and `acme-reload.sh` are the installed stand-specific renewal helpers. Operator connection settings are kept in ignored `.runtime/stand/operator.env`.
